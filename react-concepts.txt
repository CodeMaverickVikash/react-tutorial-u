1. JSX (JavaScript XML)
- Syntax extension to write HTML-like code in JavaScript
- Compiles to React.createElement() calls
- Must return a single parent element (or Fragment)

Rules:
  - Use className instead of class
  - Use htmlFor instead of for
  - camelCase attributes: onClick, onChange, onSubmit
  - Self-closing tags: <img />, <input />
  - JS expressions in curly braces: {variable}
  - Comments: {/* comment */}

Example:
  const element = <h1 className="title">Hello, {name}!</h1>;

2. COMPONENTS & PROPS
- Props: read-only data passed from parent to child
- Can be any type: string, number, object, array, function
Best Practices:
  - Destructure props for cleaner code
  - Set default values for optional props
  - Never modify props (read-only)

3. STATE (useState)
- Component's own data that triggers re-renders when changed
- Hook: const [state, setState] = useState(initialValue)

Updating Primitives:
  setCount(count + 1);
  setCount(prev => prev + 1);  // functional update (preferred)

Updating Objects (always spread):
  setUser({ ...user, name: "John" });

Updating Arrays (immutable):
  setItems([...items, newItem]);        // add
  setItems(items.filter((_, i) => i !== index)); // remove

When to use:
  - Form inputs, UI state (modals, toggles), component-specific data

4. CONDITIONAL RENDERING
  // Ternary (if-else)
  {isLoggedIn ? <Logout /> : <Login />}

  // Logical AND (show or hide)
  {hasMessages && <Notification count={count} />}

  // Early return
  if (!user) return <Login />;

  // Null to hide
  if (!show) return null;

5. LISTS & KEYS
- Use .map() to render arrays
- Each item needs a unique key prop
- Keys help React efficiently update the DOM

  {todos.map(todo => (
    <li key={todo.id}>{todo.text}</li>
  ))}

Key Rules:
  - Use unique IDs from data (not array index if list changes)
  - Never use Math.random() or Date.now() as keys
  - Keys must be unique among siblings

6. EVENT HANDLING
----------------------------------------------------------------
- Events are camelCase: onClick, onChange, onSubmit
- Pass function REFERENCE, not function call

  // Pass reference
  <button onClick={handleClick}>Click</button>

  // With parameters
  <button onClick={() => handleDelete(id)}>Delete</button>

  // Form submit
  const handleSubmit = (e) => {
    e.preventDefault();
    // handle form
  };

Common Events:
  Mouse:    onClick, onDoubleClick, onMouseEnter, onMouseLeave
  Keyboard: onKeyDown, onKeyUp, onKeyPress
  Form:     onChange, onSubmit, onFocus, onBlur

7. LIFTING STATE UP
- Move shared state to closest common parent
- Parent passes state + updater to children
- Children call updaters to communicate back

                        REACT HOOKS

8. useEffect - Side Effects
Dependency Array:
  useEffect(() => { ... });           // every render
  useEffect(() => { ... }, []);       // once on mount
  useEffect(() => { ... }, [a, b]);   // when a or b changes

Cleanup:
  useEffect(() => {
    const timer = setInterval(() => setCount(c => c + 1), 1000);
    return () => clearInterval(timer); // cleanup on unmount
  }, []);

Use for: data fetching, subscriptions, timers, DOM manipulation

NOTE: Async is NOT allowed directly in useEffect body.
  // Correct:
  useEffect(() => {
    const fetchData = async () => {
      const res = await fetch(url);
      const data = await res.json();
      setData(data);
    };
    fetchData();
  }, []);

9. useRef - Mutable References
- Does NOT trigger re-renders when updated
- Persists across renders

  const inputRef = useRef(null);
  <input ref={inputRef} />
  inputRef.current.focus(); // DOM access

  // Store mutable value (no re-render)
  const renderCount = useRef(0);
  renderCount.current++;

useRef vs useState:
  useRef  -> no re-render, for DOM access & mutable values
  useState -> triggers re-render, for UI state

10. useReducer - Complex State
- Alternative to useState for complex state logic
- Reducer: pure function (state, action) => newState
- No async/side effects inside reducer!

  const counterReducer = (state, action) => {
    switch (action.type) {
      case "INCREMENT": return { count: state.count + 1 };
      case "DECREMENT": return { count: state.count - 1 };
      case "RESET":     return { count: 0 };
      default:          return state;
    }
  };

  const [state, dispatch] = useReducer(counterReducer, { count: 0 });
  dispatch({ type: "INCREMENT" });
  dispatch({ type: "INCREASE", payload: 5 });

useReducer vs useState:
  useReducer -> complex state, multiple actions, predictable transitions
  useState   -> simple values, quick prototyping

11. useContext - Global State (No Prop Drilling)
Step 1: Create context
  const CartContext = createContext(null);

Step 2: Provide value
  <CartContext.Provider value={{ user, setUser }}>
    {children}
  </CartContext.Provider>

Step 3: Consume
  const { user, setUser } = useContext(CartContext);

Custom hook pattern (best practice):
  export const useUser = () => {
    const context = useContext(UserContext);
    if (!context) throw new Error("Must be inside Provider");
    return context;
  };

Use for: themes, auth, language, small-medium apps

12. useMemo - Memoize Expensive Values
  const filteredItems = useMemo(
    () => items.filter(item => item.name.includes(query)),
    [items, query] // only recompute when these change
  );

Use for: expensive filtering/sorting, complex calculations
Don't use for: simple math, primitive values (overhead > benefit)

13. useCallback - Memoize Functions
  const handleClick = useCallback(() => {
    console.log("Clicked:", id);
  }, [id]); // recreates only when id changes

  // Pass to memoized children without causing re-renders
  <MemoizedChild onClick={handleClick} />

Use for: functions passed to memoized child components

14. CONTEXT API vs REDUX
  Context API:
    - Simple setup, no extra library
    - Good for small-medium apps
    - No DevTools, no middleware
    - Can cause performance issues with frequent updates

  Redux Toolkit:
    - Centralized store, predictable state
    - DevTools, middleware support
    - Better for large, complex apps
    - More setup but cleaner at scale

20. CUSTOM HOOKS
- Extract reusable hook logic into functions starting with "use"

  // useFetch.js (in your project)
  export function useFetch(opt) {
    const [isFetching, setIsFetching] = useState(false);
    const [fetchedData, setFetchedData] = useState([]);
    const [error, setError] = useState();

    useEffect(() => {
      fetch(opt.url)
        .then(res => res.json())
        .then(data => setFetchedData(data))
        .catch(err => setError(err));
    }, []);

    return { isFetching, fetchedData, error };
  }

  // Usage
  const { isFetching, fetchedData } = useFetch({ url: "/api/todos" });


                   RENDERING BEHAVIOR

21. WHAT TRIGGERS RE-RENDERS
  1. State changes (useState, useReducer)
  2. Props changes
  3. Parent re-renders (children re-render by default)
  4. Context value changes (all consumers re-render)

Render Phase: pure, can be paused/interrupted
Commit Phase: applies DOM changes, runs effects (can't be interrupted)

22. COMMON RENDERING GOTCHAS
Object/Array props create new reference each render:
  // BAD - re-renders every time
  <Child user={{ name: "John" }} />

  // GOOD - stable reference
  const user = useMemo(() => ({ name: "John" }), []);
  <Child user={user} />

Functions create new reference each render:
  // BAD
  <Child onClick={() => console.log("hi")} />

  // GOOD
  const handleClick = useCallback(() => console.log("hi"), []);
  <Child onClick={handleClick} />

Never define components inside components:
  // BAD - new component every render
  const Parent = () => {
    const Child = () => <div>child</div>; // re-creates every render!
    return <Child />;
  };

  // GOOD - define outside
  const Child = () => <div>child</div>;
  const Parent = () => <Child />;

23. BATCHING (React 18+)
- Multiple setState calls in one event = single re-render
  const handleClick = () => {
    setCount(c => c + 1);
    setName("John");
    setActive(true);
    // Only 1 re-render!
  };


                    RULES OF HOOKS
1. Only call hooks inside functional components
2. Only call hooks at the top level (not in loops, conditions, nested functions)
3. Custom hooks must start with "use"

                     PERFORMANCE TIPS

1. Measure first with React DevTools Profiler
2. React.memo   -> prevent child re-renders, for example - you have used child comp in parent comp when any state of parent change, child rerender, to prevent this we use React.memo in child component, this only re-render when it's prop change.
3. useMemo      -> memoize expensive calculations - you have expensive calculation on variable or in a function, when you update any state of component, re-render comp and it's content, so expensive also re-run, instead you can wrap expensive logic in useMemo and let him decide when this will run similar to useEffect dependency array.
4. useCallback  -> memoize function props
5. Keep state close to where it's used
6. Split Context by update frequency
7. Use keys correctly in lists
8. Code splitting: React.lazy + Suspense for large components
9. Virtualize long lists (react-window)
10. Debounce search inputs
